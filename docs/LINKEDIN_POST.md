## 1. Versão técnica

**Como transformar um score de anomalia em uma investigação explicável?**

Construí o FraudLens, uma plataforma full stack que gera pagamentos sintéticos, cria features temporais sem olhar o futuro, combina Isolation Forest com 13 regras configuráveis e expõe cada evidência em um dashboard Next.js.

Diferenciais: seed reproduzível, testes contra target leakage, score decomposto, métricas por cenário, drift exploratório, API FastAPI, SQLite/PostgreSQL, Docker e threat model.

O principal aprendizado: explicabilidade não é um componente visual; ela precisa nascer junto dos dados e da lógica de scoring.

Código e documentação: https://github.com/GabrielBuck/fraudlens

## 2. Versão para recrutadores

**Um único projeto para conectar dados, software, IA e segurança.**

No FraudLens, pagamentos 100% fictícios percorrem um fluxo completo: geração, detecção de comportamento atípico, explicação, visualização e revisão humana.

Desenvolvi backend, dashboard, modelo não supervisionado, regras de risco, testes, Docker, CI e documentação executiva. O produto deixa claro que um alerta não condena: ele prioriza o que merece contexto.

Veja a demonstração e o estudo de caso: https://github.com/GabrielBuck/fraudlens

## 3. Storytelling

Eu comecei com uma pergunta: **“como eu explicaria um alerta técnico para alguém que precisa tomar uma decisão?”**

A resposta virou o FraudLens. Primeiro vieram os dados sintéticos. Depois, o cuidado para nenhuma transação futura contaminar o passado. Em seguida, modelo e regras. Por fim, uma interface que mostra não só “quanto risco”, mas “por quê” e “o que aconteceu antes e depois”.

O aprendizado mais valioso não foi uma biblioteca. Foi projetar limites: score não é culpa, métrica sintética não é resultado de produção e automação não substitui revisão responsável.

Projeto completo: https://github.com/GabrielBuck/fraudlens
